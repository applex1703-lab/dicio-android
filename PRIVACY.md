# Privacy notes for the personal TV fork

This fork is not offline-only. The following describes the app's implementation, not a guarantee about third-party services or every Android device.

## Voice and external services

Background preparation is **off by default**. If explicitly enabled in Settings → Input and output methods → «Фоновая подготовка Google», while Dicio is the active TV assistant its existing voice interaction service attempts an explicit background binding to Google's Katniss recognition service as a latency experiment. This can start or keep Google's service in memory and consume memory, CPU or power for as long as the assistant service remains active; no latency or resource benefit has been established. Dicio does not create a recognizer, invoke the microphone or call `startListening` for this prebind, and does not pass foreground capabilities to it. Binding itself may cause Google or the device to perform actions, including microphone or network activity; Dicio cannot guarantee otherwise.

On Android 11 (API 30), only when the device reports manufacturer TCL, an explicitly requested voice session may skip the usual six-second settling wait if the opted-in prebind had reported a connection at request time, Dicio has not processed a notification invalidating that connection generation, and Google microphone AppOps reports ALLOWED after the session's separate capability-including bind. Otherwise the original wait applies. A disconnect or capability change can race with these checks: a notification may be delayed or arrive after the final check, so this does not prove that the connection remained continuously available or that the capability is present at the moment of recording. Manufacturer identification may exclude TCL devices reporting another brand, or include other TCL models; this is an experimental heuristic, not a device certification. Neither a connected prebind nor AppOps ALLOWED guarantees that Google has the microphone capability on every device: recognition error 9 remains possible. There is no automatic retry, including after error 9, and no background recording.

Turning the switch off immediately requests unbinding on the main thread; Dicio also requests unbinding on assistant shutdown, destruction, connection failure or if no connection callback arrives within 10 seconds (the main-thread timer can run late). If a bind call is still in progress, unbinding is deferred until it returns. Successful release is not guaranteed, and does not guarantee that Android or another client stops Google or removes it from memory. If release fails, `DicioPrebind` logs `prebind_unbind_uncertain`; its state is uncertain and further prebinds are blocked in that process. There is no hidden retry: another attempt requires explicitly switching off and on, or a new assistant service instance while enabled. An explicit re-enable during an in-progress bind waits for the prior release and is blocked if release is uncertain. The process-wide limit applies **only to background prebinds**, not to the independent session recognition bindings, which can run in parallel, or the separate manual diagnostic. Android process termination ends Dicio's bindings.

The `DicioPrebind` log tag records connection, refusal, timeout and release outcomes without voice content. These logs do not prove what Google's service does: check device microphone indicators, process state and resource usage independently. Disabling this prebind does not disable recognition explicitly requested during a voice session or the separate manual bind diagnostic.

When a TV voice session is invoked and microphone permission is available, Dicio requests one-shot recognition from Google's explicitly selected Katniss recognition service. Google receives the audio needed for recognition; whether it is processed locally or remotely depends on Google and the device. Dicio receives recognized text. Consult Google's policies for its handling of voice data. Do not assume recognition works without a network connection.

If RouterAI is enabled, the recognized or entered request, model ID, a catalog of eligible installed app labels and IDs, and available media-session labels, states and supported operations are sent to RouterAI's chat completions endpoint. The API key is sent for authentication. Media titles and media IDs used to verify player feedback remain local in this implementation. Consult RouterAI's policies for its handling of submitted data. The model's decision is validated locally, but model answers and actions can still be wrong.

When RouterAI asks a clarification question, the preceding request and question are kept only in process memory. The context is eligible for the next explicit input in the same input scope for 60 seconds, and its age is checked again before the request is passed to the network. Network queuing or other delays can cause the request to be transmitted later; once sent, it cannot be retracted. TV voice sessions share a process-local scope across window recreation; Home and external inputs do not share it. This is not a conversation history and is not saved to disk. The context is consumed once or discarded on cancellation, error, scope change, or expiry; closing a completed voice session normally does not discard it. Physical removal by the timer can be delayed while the process or device is suspended. Device actions suggested in a response that used this context require a new complete command.

Android text-to-speech handles spoken responses during a session. Its processing and any network use depend on the chosen system engine and its provider. The inherited skills used when RouterAI is disabled may also contact external services and send information needed for a request, such as a search query or location. Connectivity and service availability vary; disabling internet access is not guaranteed to leave the assistant functioning normally.

## Permissions and local data

`MediaAccessService` uses Android notification-listener access to query active media sessions. Its implementation has no notification callbacks and does not read notification contents, but the system permission is broad notification access, not a media-only permission. Review this access in Android settings before granting it; media controls may not work without access. The app also requests permissions for features such as microphone input and package discovery.

Preferences and other app data are stored locally. Requests and answers can appear in the app's interaction display; diagnostic logs may contain operational information or errors, so do not assume logs contain no sensitive information. RouterAI settings are stored outside backup; the API key is encrypted using an Android Keystore key. This is not a guarantee against a compromised device or service.

You can reset RouterAI settings in the app and clear app storage or uninstall the app to remove its local data. This does not delete data already received or retained by Google, RouterAI, a TTS provider or other external services; consult their policies and controls.
